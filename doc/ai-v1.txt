Проанализировать каким образом устроен Proof-Of-Work на странице [https://nosql.ru/forum/forum.php?fid=8](https://nosql.ru/forum/forum.php?fid=8)

При первом визите браузеру предлагается сделать некие вычисления с хеш-суммами с помощью JS и отправить результат обратно, получив редирект-пропуск к реальной странице.

Я думаю что при обращении к [https://nosql.ru/forum/forum.php?fid=8](https://nosql.ru/forum/forum.php?fid=8) мы получим редирект на botcheck/challenge.php с какими-то параметрами, где будет находиться JS-код выполняющий proof-of-work и отправляющий результат на сервер, после чего сервер пришлёт cookie подтверждающие прохождение proof-of-work и редирект уже на настоящую [https://nosql.ru/forum/forum.php?fid=8](https://nosql.ru/forum/forum.php?fid=8)

Можно ли реализовать на golang простое консольное приложение для linux ubuntu которое получит параметры proof-of-work задачки, решит задачку, отправит результат и сохранит полученные cookies в файл для дальнейшего похода на сайт?

golang приложение не должно запускать никаких JS-виртуальных машин и исполнять JS-код с этого сайта. Нужно повторить логику вычисления proof-of-work в golang-коде, это будет работать быстрее.

Для работы этого golang proof-of-work алгоритма понадобятся какие-то параметры, типа challenge и другие, которые придётся попарсить из сетевого обмена или JS-кода возможно, но может быть получится обойтись только анализом http-заголовков.

Пример запуска приложения:

./app --url [https://nosql.ru/forum/forum.php?fid=8](https://nosql.ru/forum/forum.php?fid=8) --outcookie filename.txt --out file.txt --outheader headers-out.txt

--url -- URL куда идти

--outcookie -- куда сохранить результирующие cookie после получения перенаправления на нормальную страницу после решения задачки proof-of-work

--cookie filename.txt -- если эта опция есть, то для первоначального запроса используются cookie из файла filename.txt и возможно при этих cookie задача proof-of-work выдана не будет и страница откроется сразу.

--out file.txt -- файл в который нужно записать BODY из http-ответа с финальной страницей (которую придётся запросить после получения редиректа после отправки proof-of-work решения задачи)

--outheader -- файл в который нужно записать ответные финальные HTTP headers

--stdoutheaders -- выводить все HTTP-запросы с заголовками всех отправляемых и принимаемых запросов в консоль, но без BODY этих запросов. Перед запросом выводить время в формате year-mon-day hour:min:sec.millisec

Любой из параметров может отсутствовать.

Обязательные параметры только: --url

Формат хранения и считывания Cookie из файла сделать простым:

key1=value1

key2=value2

...

Сохранять для каждой cookie пути, домены или время действия и любые другие параметры - не нужно, пусть cookie будут тупыми и вечными.

Приложение должно работать через HTTP2 и ipv6 или HTTP/1.1 и ipv4 при невозможности первых.

Приложение должно вывести в консоль параметры совершённой вычислительной работы proof-of-work после её завершения.

Код приложения и его сообщения в консоли не должны содержать киррилических строк или комментариев, при необходимости выводить какой-то текст или комментировать код - только английский язык.

Снабдить код [README.md](http://README.md) оформленный кратко в стиле man pages описывающий смысл параметров commandline.

[README.md](http://README.md) должен содержать секции: (1) как собрать приложение, (2) описание commandline опций, (3) описание proof-of-work системы входа на этот сайт.
